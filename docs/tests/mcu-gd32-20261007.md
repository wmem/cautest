# GD32F427 真实 MCU 验证（2026-10-07）

本次使用 Cautest 直接 CLI 和 Make，没有调用或修改 Xmake 接入。版本基于 Cautest `6f2fdaa` 的本次工作区改动，依赖 GD32 MSP `073fa12af80c4a641ea85fcf0a6a243a13bd4977`。板端为 GD32F427VET6，25 MHz 外部晶振、200 MHz 系统时钟，USART0 PA9/PA10；探针为 CMSIS-DAP v2 `CA6BCA57C554B615`，串口 `/dev/ttyUSB0`、115200 8N1，pyOCD 0.45.1。

示例与复现入口见[真实 MCU 使用说明](../usage/mcu-real.md)。结果和下载尝试保存在[结构化记录](evidence/mcu-gd32-20261007/results.json)，原始执行日志与结果一同维护。

正常固件 ELF 的 text 为 21588 字节、data 为 4 字节、bss 为 5352 字节；`arm-none-eabi-nm -u` 无未解析符号。交叉编译采用 `-Wall -Wextra -Werror`，本次修复 ARM 枚举无符号类型导致的范围检查告警。公共接口与协议另经过 Host 和 ARM 的 `-ffreestanding -fno-builtin -nostdinc` 编译及 libc/heap 未解析符号检查；C 回归覆盖分片、暂无数据、BYE、重新初始化、负数/越界枚举与收发错误，并额外通过 Host `-fshort-enums` 检查。TS 构建、类型检查、MCU/协议/Native 回归、安装后 MCU 库链接、便携包及文档链接检查通过。

多次下载实际出现 1 MHz 失败，随后 100 kHz 烧录和逐段读回通过。1 MHz 也有成功记录，不能据此判断长期稳定；复位及 Boot ID 注入始终使用 100 kHz。`Invalid coresight component, cidr=0x0` 警告仍出现，不影响本轮已通过的记录，不据此声明根因已解决。

验证范围是通用 C 运行时和协议在物理 MCU 上的集成，以及基础时钟/UART 检查。没有验证 SPI 物理通信、UART 全模式、中断/DMA、看门狗隔离、HardFault 恢复或其他 MCU 的实际板卡。挂死测试只能由 Host 超时停止等待，并通过平台复位恢复；当前 GD32 示例不抢占测试。
